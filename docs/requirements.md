# Требования к системе. ИС управления автосервисом

Версия документа: 0.1 (черновик)
Статус: на согласовании

## 1. Контекст

Документ описывает требования к информационной системе управления автосервисом (далее — Система). Система автоматизирует учёт клиентов, автомобилей, заказ-нарядов, работ и запчастей. Подробное описание предметной области — в [глоссарии](glossary.md).

## 2. Обозначения приоритетов

| Приоритет | Значение |
|---|---|
| **Критично (К)** | Без требования система не выполняет основную функцию — обязателен для MVP |
| **Важно (В)** | Значительно повышает ценность системы — включается во вторую итерацию |
| **Желательно (Ж)** | Улучшение, реализуемое при наличии времени |

## 3. Функциональные требования

### 3.1. Учёт клиентов

| ID | Требование | Приоритет |
|---|---|---|
| FR-1.1 | Система хранит карточку клиента: ФИО, телефон, e-mail (необязательно), примечание | К |
| FR-1.2 | Система позволяет создать, редактировать и удалять карточку клиента | К |
| FR-1.3 | При удалении клиента с существующими заказ-нарядами система выполняет мягкое удаление (архивация) | В |
| FR-1.4 | Поиск клиента по ФИО, телефону или госномеру автомобиля | К |

### 3.2. Учёт автомобилей

| ID | Требование | Приоритет |
|---|---|---|
| FR-2.1 | Система хранит карточку автомобиля: VIN, марка, модель, год выпуска, госномер, пробег | К |
| FR-2.2 | Автомобиль привязывается к клиенту; у клиента может быть несколько автомобилей | К |
| FR-2.3 | При добавлении заказ-наряда актуальный пробег фиксируется в наряде и обновляется в карточке автомобиля | В |

### 3.3. Заказ-наряды

| ID | Требование | Приоритет |
|---|---|---|
| FR-3.1 | Система создаёт заказ-наряд с привязкой к клиенту и автомобилю | К |
| FR-3.2 | Заказ-наряд содержит статус: «принят», «в работе», «ожидает согласования», «готов», «выдан», «отменён» | К |
| FR-3.3 | Система позволяет добавлять в наряд позиции работ и запчастей с ценами | К |
| FR-3.4 | Система хранит комментарий мастера и жалобы клиента, зафиксированные при приёме | В |
| FR-3.5 | Система автоматически меняет статус наряда на «готов» при завершении всех работ (вручную — через интерфейс) | В |
| FR-3.6 | Система даёт возможность отменить наряд с указанием причины | В |

### 3.4. Справочники работ и запчастей

| ID | Требование | Приоритет |
|---|---|---|
| FR-4.1 | Система хранит справочник работ: наименование, цена, нормо-часы | К |
| FR-4.2 | Система хранит номенклатуру запчастей: наименование, артикул, цена, единица измерения | К |
| FR-4.3 | Справочники редактируются через интерфейс (добавление, изменение, деактивация) | В |

### 3.5. Склад

| ID | Требование | Приоритет |
|---|---|---|
| FR-5.1 | Система ведёт остатки запчастей на складе | К |
| FR-5.2 | При включении запчасти в заказ-наряд остаток уменьшается; при отмене наряда — восстанавливается | К |
| FR-5.3 | Поступление запчастей оформляется как операция прихода с указанием количества и цены | В |
| FR-5.4 | Если запчасти нет в остатке, система помечает позицию наряда как «под заказ» | В |

### 3.6. Финансы и отчётность

| ID | Требование | Приоритет |
|---|---|---|
| FR-6.1 | Система формирует счёт по заказ-наряду (работы + запчасти, итоговая сумма) | К |
| FR-6.2 | Система фиксирует факт оплаты (полной или частичной) | В |
| FR-6.3 | Отчёт по выручке за период (по дням/месяцам) | Ж |
| FR-6.4 | Загрузка сервиса: количество нарядов и сумма по каждому механику за период | Ж |

### 3.7. Гарантия

| ID | Требование | Приоритет |
|---|---|---|
| FR-7.1 | Система хранит гарантийный срок по позициям наряда (работы и запчасти) | Ж |
| FR-7.2 | При повторном обращении по гарантии система отмечает связь с исходным нарядом | Ж |

## 4. Нефункциональные требования

| ID | Требование | Приоритет |
|---|---|---|
| NFR-1 | Система работает через веб-интерфейс и REST API | К |
| NFR-2 | Данные хранятся в СУБД PostgreSQL | К |
| NFR-3 | Время отклика API на типовые запросы (списки, поиск) — не более 300 мс на объёме до 10 000 записей | В |
| NFR-4 | Все изменения данных логируются (кто, что, когда) | Ж |
| NFR-5 | Пароли пользователей хранятся в хэшированном виде | К |
| NFR-6 | Интерфейс адаптирован для работы на планшете (основное рабочее место мастера-приёмщика) | В |
| NFR-7 | Резервное копирование базы данных — ежедневное (реализуется на уровне инфраструктуры) | Ж |

## 5. Вне рамок первой версии

- Онлайн-запись клиентами через сайт/мессенджер.
- Интеграция с онлайн-кассами и 1С.
- Мобильное приложение для клиентов.
- Учёт нескольких филиалов.
- Генерация первичных документов (печать наряда, акта).

## 6. Открытые вопросы

1. Нужна ли авторизация с ролями в MVP или достаточно единого доступа?
2. Принимать ли к оплате одновременно работы и запчасти одним счётом — подтверждено: да (FR-6.1).
3. Хранить ли историю цен на работы и запчасти — предложение: да, для корректных счётов по старым нарядам.
