# Модель вариантов использования. ИС управления автосервисом

Версия: 0.1
Статус: черновик

## 1. Акторы

| Актор | Описание | Потребности |
|---|---|---|
| **Клиент** | Владелец автомобиля, заказывающий работы | Записаться, сдать автомобиль, получить готовый автомобиль и счёт |
| **Мастер-приёмщик** | Сотрудник, работающий в системе большую часть смены | Оформить наряд, согласовать смету, выдать автомобиль |
| **Механик** | Сотрудник, выполняющий работы | Отмечать выполнение работ, запрашивать запчасти |
| **Управляющий** | Руководитель сервиса | Смотреть загрузку, выручку, остатки склада |

## 2. Сводная диаграмма вариантов использования

Диаграмма: `diagrams/use-case.drawio` (экспорт: `diagrams/use-case.png`).

## 3. Варианты использования (детально)

### UC-1. Запись клиента на обслуживание
- **Актор:** Клиент
- **Предусловие:** —
- **Результат:** создана/подтверждена запись на дату и время
- **Основной поток:**
  1. Клиент связывается с сервисом (телефон, лично).
  2. Мастер-приёмщик проверяет расписание.
  3. Фиксируется дата, время и контакт клиента.
  4. Система сохраняет запись.
- **Альтернативы:**
  - 3a. Выбранное время занято — предлагается ближайшее свободное.

### UC-2. Приём автомобиля и оформление заказ-наряда
- **Актор:** Мастер-приёмщик
- **Предусловие:** клиент и автомобиль есть в системе (или создаются)
- **Результат:** создан заказ-наряд со статусом «принят»
- **Основной поток:**
  1. Мастер-приёмщик находит клиента (по ФИО/телефону/госномеру).
  2. Выбирает автомобиль; при необходимости создаёт.
  3. Фиксирует жалобы клиента и показания одометра.
  4. Создаёт заказ-наряд; система сохраняет его со статусом «принят».
- **Альтернативы:**
  - 1a. Клиент не найден — создаётся новая карточка клиента (UC-5).

### UC-3. Назначение работ и формирование сметы
- **Актор:** Мастер-приёмщик
- **Предусловие:** заказ-наряд открыт
- **Результат:** наряд содержит работы и запчасти, статус «ожидает согласования»
- **Основной поток:**
  1. Мастер-приёмщик добавляет в наряд работы из справочника.
  2. Добавляет необходимые запчасти.
  3. Система рассчитывает сумму сметы.
  4. Статус наряда меняется на «ожидает согласования».
- **Альтернативы:**
  - 2a. Запчасти отсутствуют на складе — позиция помечается «под заказ».
  - 4a. Клиент не согласовал смету — наряд возвращается в «принят» с комментарием.

### UC-4. Выполнение работ и закрытие наряда
- **Актор:** Механик
- **Предусловие:** наряд в статусе «в работе»
- **Результат:** наряд в статусе «готов», запчасти списаны
- **Основной поток:**
  1. Механик отмечает по каждой работе статус выполнения.
  2. Система списывает запчасти со склада.
  3. После завершения всех работ наряд переходит в «готов».
- **Альтернативы:**
  - 1a. Обнаружены доп. неисправности — механик возвращает наряд в «ожидает согласования» с комментарием.

### UC-5. Ведение карточки клиента
- **Актор:** Мастер-приёмщик
- **Предусловие:** —
- **Результат:** карточка клиента создана/обновлена
- **Основной поток:**
  1. Мастер-приёмщик создаёт карточку (ФИО, телефон).
  2. При необходимости редактирует.
- **Альтернативы:**
  - 1a. Клиент уже существует — карточка обновляется.

### UC-6. Выдача автомобиля и оплата
- **Актор:** Мастер-приёмщик
- **Предусловие:** наряд в статусе «готов»
- **Результат:** наряд «выдан», зафиксирована оплата
- **Основной поток:**
  1. Мастер-приёмщик передаёт автомобиль клиенту.
  2. Клиент оплачивает счёт (полностью или частично).
  3. Система фиксирует оплату и переводит наряд в «выдан».
- **Альтернативы:**
  - 2a. Оплата безналичная через терминал — сумма фиксируется из поступления от эквайринга.

### UC-7. Управление справочниками (работы, запчасти)
- **Актор:** Мастер-приёмщик / Управляющий
- **Предусловие:** есть роль с правом редактирования
- **Результат:** справочник обновлён
- **Основной поток:**
  1. Пользователь добавляет/изменяет позицию.
  2. Система сохраняет изменение.
- **Альтернативы:**
  - 1a. Позиция используется в нарядах — редактируется только наименование/цена, без удаления (деактивация).

### UC-8. Операции со складом
- **Актор:** Мастер-приёмщик
- **Предусловие:** —
- **Результат:** остатки корректны
- **Основной поток:**
  1. Оформляется приход запчастей.
  2. При включении запчасти в наряд остаток уменьшается.
  3. При отмене наряда остаток восстанавливается.

### UC-9. Просмотр отчётов
- **Актор:** Управляющий
- **Предусловие:** есть роль с правом просмотра отчётов
- **Результат:** отчёт за период
- **Основной поток:**
  1. Управляющий выбирает тип отчёта и период.
  2. Система формирует и отображает отчёт.
- **Альтернативы:**
  - 1a. Данных за период нет — отчёт пустой с пометкой «нет данных».
